Native first, fewer overlaps

The former Shield, tool-context and RSI packages are retired from this candidate's active install catalog. They are not folded into Privacy Guard merely to reduce the folder count.

  • Safety: use native command approvals, tool-loop/failure guardrails and file-write baseline checks. These overlap Shield but do not reproduce every old threshold or policy.
  • Learning: use native skill self-improvement and /learn. A separate heuristic lesson engine has not demonstrated extra benefit.
  • Context: use native tool guidance and date/time queries when needed. The former automatic per-turn UTC injection is not retained.

Preserve identity and rollback

Human names are clearer; runtime IDs and skill namespaces stay stable. Removing source folders does not uninstall existing copies.

  1. Stop a disposable test profile and back up its pinned plugins, configuration and data together.
  2. Check host compatibility. Update the retained plugin and remove old separate/retired plugins through native management.
  3. Restart with a fresh session. Check the three retained packages, one privacy output hook and the unchanged required-policy owner.
  4. If verification fails, stop and restore the pinned plugin/config snapshot together. Do not turn off required privacy to hide an error.

Existing RSI_LESSONS.md and session metrics are not deleted or automatically imported as native skills. Retired source remains preserved separately for rollback, outside active discovery.

What this does not prove

Local synthetic tests are not evidence of every provider path, a process-wide privacy boundary or installed laptop behavior. The matching required-privacy core is closed and unadopted. No daily profile has been migrated. The uploaded 278-case matrix includes retired-policy targets and policy questions; it is not an all-green certification.
